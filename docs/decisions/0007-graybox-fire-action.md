# ADR 0007：加入受限的灰盒开火反馈

- **状态：** 接受
- **日期：** 2026-08-23
- **决策者：** 项目所有者与 Codex

## 背景

项目所有者在完成山顶枪支拾取后，希望枪支可以开火。当前 MVP 原本明确不做战斗；若直接加入敌人、伤害、弹药和完整武器系统，会显著扩大范围。

## 决定

拾取枪支后允许玩家使用鼠标左键开火。开火采用短冷却和可见的灰盒弹道线，并在 HUD 记录开火次数；本节点不实现敌人、命中伤害、弹药、音效或战斗循环。

## 原因

- 直接回应开火交互需求，同时保持实现可逆、可验证。
- 可见弹道和冷却足以验证第一人称开火反馈，不需要先建立完整战斗系统。
- 继续使用程序化灰盒资产，避免引入未登记的外部武器资产。

## 后果

### 正面

- 玩家能明确感知“已装备”和“已开火”。
- 后续若决定扩展战斗，可以在已验证的输入与状态基础上继续设计。

### 代价与风险

- 纵切不再是完全无战斗交互，需要在儿童体验和章节语境中重新评估枪支意象。
- 没有目标或伤害时，开火仍只是技术原型，不应误称为完整战斗。

## 备选方案

- **只保留拾取：** 范围最小，但不能满足本次明确的开火需求。
- **直接加入敌人和伤害：** 超出当前纵切的验证目标，暂不采用。

## 后续验证

- 普通浏览器中确认未拾取前左键无效，拾取后左键生成一次弹道且受冷却限制。
- 若要加入命中、伤害、敌人或弹药，先重新评估 MVP 并新增相应 ADR。
