# ADR 0006：先加入非战斗道具拾取原型

- **状态：** 接受
- **日期：** 2026-08-23
- **决策者：** 项目所有者与 Codex

## 背景

项目所有者希望在绿色山顶放置一把枪，并在玩家接触时获得它。当前 MVP 明确暂不制作战斗、敌人、生命值或生存数值；直接加入射击系统会扩大产品范围，也会削弱阅读伴侣的首阶段定位。

## 决定

加入一把程序化灰盒枪支作为非战斗拾取道具：玩家接触后道具从场景中隐藏，HUD 显示已获得状态，但本节点不实现开火、弹药、敌人、伤害或武器使用。

## 原因

- 满足“山顶有物品、碰到即可获得”的交互验证目标。
- 保留未来扩展的道具状态接口，同时不引入完整战斗循环。
- 程序化灰盒资产可复现、易调整，不引入未经登记的外部美术资产。

## 后果

### 正面

- 可以验证传送、探索和拾取之间的空间体验。
- 道具状态可在 HUD 中直接核对。

### 代价与风险

- “枪”这一视觉符号仍可能让体验偏向传统游戏；正式章节内容和美术需要重新审视其是否符合阅读目标。
- 若后续要求射击或战斗，必须另行评估并更新 MVP/ADR，不从本原型隐式扩展。

## 备选方案

- **直接实现射击系统：** 当前范围和内容约束不接受。
- **放置普通工具或书本：** 更符合阅读伴侣，但没有满足本次明确的枪支交互请求。

## 后续验证

- 在普通浏览器中确认山顶枪支可见、接触后只拾取一次、HUD 状态稳定。
- 若要增加开火、敌人或伤害，先更新 MVP 范围并新增专门 ADR。
