# ADR 0003：章节是同一座岛的全局时间切片

- **状态：** 接受
- **日期：** 2026-08-12
- **决策者：** 项目所有者与 Codex

## 背景

传统地图把后期才建造、发现或命名的地点全部同时展示，容易造成剧透，也无法表达林肯岛随故事发生的变化。为每一章复制完整场景又会产生大量重复和状态漂移。

## 决定

始终维护同一座逻辑上的林肯岛。选择章节时，系统解析并应用该章对应的：

- 稳定自然地理。
- 截至该章已发生的建设与环境变化。
- 本章人物路线和阅读锚点。
- 读者在该章已经可以知道的名称、入口和解释。

物体的物理存在、地图可见、名称可见和说明可见必须能够分别控制。

## 原因

- 与“整座岛处于这一章状态”的阅读直觉一致。
- 能自然表达文明逐步建立的过程。
- 防止地图标签和模型提前泄露后续内容。
- 共享地理基础，避免为每章复制和维护整座岛。

## 后果

### 正面

- 章节切换可以复用相同坐标、地形和资产。
- 世界变化与知识揭示都能形成可查询的时间线。
- 未来可以比较章节、展示建设演变或回放路线。

### 代价与风险

- 数据模型比简单的场景开关更严格。
- 必须逐章考证地点何时存在、被发现、命名和解释。
- 小说可能存在模糊、矛盾或不同译本编号差异，需要记录假设和出处。

## 备选方案

- **每章一个 Unity Scene：** 初期直观，但重复严重，难以保持全岛一致。
- **永远展示最终状态地图：** 实现简单，却失去时间维度并造成剧透。
- **只在当前地点切换状态：** 无法满足“无论人在岛上哪里，整座岛都属于该章”的设计意图。

## 后续验证

用至少两个相隔明显的章节做数据实验：同一坐标的自然地理保持稳定，建设对象和知识标签按章节正确变化，且不复制完整场景。
