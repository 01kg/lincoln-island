# ADR 0001：以 AGENTS.md 为入口的仓库记忆

- **状态：** 接受
- **日期：** 2026-08-12
- **决策者：** 项目所有者与 Codex

## 背景

项目将长期由人类与不同 AI 协作者共同推进。聊天上下文会丢失、压缩或无法传给下一个协作者；单一超长说明文件又容易混合愿景、临时状态和实现细节，最终失去可信度。

## 决定

采用文件化、分层的仓库记忆：

- 根目录 `AGENTS.md` 是强制入口与维护协议。
- `VISION.md` 和 `MVP.md` 保存稳定的产品意图。
- `NOW.md` 保存会被替换的当前快照和交接状态。
- `decisions/` 保存重要选择及其原因。
- 代码、测试和 `ARCHITECTURE.md` 保存实现事实。

## 原因

- 所有信息随版本控制传播，不依赖特定 AI 厂商或会话。
- 不同寿命的信息分开维护，可以减少过期内容污染长期愿景。
- ADR 使未来协作者理解决定背景，而不只是看到结果。
- `NOW.md` 提供直接可执行的下一步，降低接手成本。

## 后果

### 正面

- 新协作者有固定阅读顺序。
- 产品决定、当前状态和代码事实更容易核对。
- 交接与审查可以通过普通文件差异完成。

### 代价与风险

- 每项实质变更都需要顺手维护相关记忆。
- 若机械追加而不删除过期内容，`NOW.md` 仍可能退化为日志。
- 文档无法自动保证真实，仍需测试和代码验证。

## 备选方案

- **仅使用 README：** 简单，但会迅速混入受众说明、开发步骤、状态与决定历史。
- **仅依赖聊天记忆：** 接手能力差，且不能随代码审查。
- **记录每次会话全文：** 信息量大但信噪比低，也可能保存不应进入仓库的内部推理。

## 后续验证

当新协作者无法只凭规定阅读顺序回答“项目是什么、现在做到哪里、下一步是什么、关键决定为什么”时，重新调整结构。
